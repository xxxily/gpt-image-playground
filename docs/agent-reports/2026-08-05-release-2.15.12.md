## 问题与解决

| 问题                                                                      | 解决办法                                                                                                     | 剩余风险                                                          |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 上个会话因大负载中断                                                      | 只从原始会话抽取用户文本和任务摘要，不读取工具大回显；生图响应落临时文件，终端只输出状态与尺寸；并发限制为 2 | 后续批量生成仍应避免把 base64、完整 HTTP 响应或大文件列表注入会话 |
| 官方图片 CLI 只接受 `b64_json`，兼容端点返回临时 URL                      | 使用用户已授权的直接 HTTP 请求，响应与下载 URL 只在临时目录；下载完成即删除                                  | 外部端点和 CDN 的兼容性、可达性与费用仍由其服务质量决定           |
| 本机透明代理把 CDN 域名解析到 `198.18.1.28`                               | 查询公开 A 记录，只对单次 CDN 下载使用 `curl --resolve`，不修改系统、Codex 或项目代理配置                    | CDN 地址变化时需要重新查询，不能把固定地址长期写入代码            |
| 兼容端点对 1536×1024 连续 500                                             | 中止无效批次，改用稳定的 1024×1024 方形母图和三种可裁切布局                                                  | 首版素材适合专题卡和案例说明，不作为高分辨率商业成片              |
| 所有内置素材改成 remote-image 后，旧测试按“第一个 remote-image”选托管媒体 | 测试改为按专题封面资产 ID 精确定位托管对象                                                                   | 新增媒体类型时继续避免依赖数组顺序                                |
| 161 Debian archive 第一次连接失败，第二次 Node headers TLS 重置            | 两次失败均停在 129 切换前；确认精确 headers URL 恢复为 HTTP 200 后第三次受控重试成功                          | Debian 10 archive、Node headers 和 npm Registry 仍有外部源抖动风险 |
| systemd 切换日志记录旧进程 status 130                                     | 复核这是旧进程正常停止；新服务 `active/running`、`NRestarts=0`、`ExecMainStatus=0`                           | 无运行故障；后续仍应区分切换停止记录与新进程失败                  |
