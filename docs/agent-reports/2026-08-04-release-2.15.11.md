## 问题与解决

| 问题 | 解决办法 | 剩余风险 |
| ---- | -------- | -------- |
| 静态导出服务端看不到 query，浏览器首帧直接渲染详情 | 首帧保持目录默认态，挂载后消费 deep-link | 挂载前会短暂保留静态目录壳，这是避免 hydration 错误的预期行为 |
| `beforeInteractive` 已把文档语言改成英文，Provider 首帧也按英文渲染 | Provider 首帧固定默认语言，effect 再载入保存配置 | 用户可见切换发生在 hydration 后，但不会丢失语言设置 |
| 未来案例保存合成 v1 recipe | 改为 executable/read-only 联合类型，归一化时彻底丢弃未知 recipe 对象 | 正式 catalog schema v2 仍需独立协议升级 |
| `v2.15.10` 扩展缓存占用旧 v1 key | 识别无 contract 旧条目，按扩展规则清洗并迁移新 key | 迁移仅保留一个发布周期，后续可评估删除旧 key 兼容路径 |
| 部署覆盖远端 `.env` 后后台 500 | 构建环境剔除 secret，部署端继承远端受控赋值，拒绝空/纯空白值，并严格验证登录跳转 | 首次部署仍需显式提供认证 secret |
| 161 Docker DNS 被 Clash fake-IP 影响，Debian archive、Node 与 npm 域名不可达 | 只在 detached 部署 worktree 的一次性 Docker 命令中为 `archive.debian.org`、`nodejs.org`、`registry.npmjs.org` 增加精确 `--add-host`；未修改 tag、运行包逻辑或 161 主机网络 | workaround 未进入已公开 tag；后续应在构建基础设施层解决 DNS/归档源可靠性 |
| Mac Docker 回退取得错误平台的 `better-sqlite3` | 部署脚本的 ELF 平台校验拒绝错误产物，未上传或激活；修复 161 构建网络后重新生成 Linux x64 native 模块 | Mac 回退仍需独立完善跨架构 native rebuild 保障 |
| 129 正式激活误判有效 secret 为空 | 定位到 Debian 10 自带 `mawk 1.3.3` 对 `[^[:space:]]` 不兼容，改用显式空格、Tab、CR 集合并在真实 129 环境回归 | 旧系统工具链仍需在后续基础设施升级中整体更新 |
| tag 发布后才确认部署脚本兼容性修复 | 保持已公开且已有下载产物的 annotated tag 不变，将兼容修复作为 `4dbb527` 推送到 `master`；生产部署使用同等修复完成激活 | 从原始 tag 再次部署时需使用 `master` 中的修复脚本或后续包含该提交的新 tag |
| 真实 AI 案例缺少可审计生成链 | 媒体记录新增来源类型、模型、配方版本、生成时间、候选次数与人工审核；上传和发布双重校验，旧库安全迁移 | 结构能力已完成，但默认 24 个真实案例资产仍需正式生成和人工审核 |
| RustSec `quick-xml` 两项高危公告 | 验证直接升级受 `plist ^0.39.2` 阻止；`plist 1.10.0` 又要求 Rust 1.88 | 随 Tauri 工具链与项目 MSRV 升级统一处理 |
