## 问题与解决

| 问题 | 解决办法 | 剩余风险 |
| ---- | -------- | -------- |
| 静态导出服务端看不到 query，浏览器首帧直接渲染详情 | 首帧保持目录默认态，挂载后消费 deep-link | 挂载前会短暂保留静态目录壳，这是避免 hydration 错误的预期行为 |
| `beforeInteractive` 已把文档语言改成英文，Provider 首帧也按英文渲染 | Provider 首帧固定默认语言，effect 再载入保存配置 | 用户可见切换发生在 hydration 后，但不会丢失语言设置 |
| 未来案例保存合成 v1 recipe | 改为 executable/read-only 联合类型，归一化时彻底丢弃未知 recipe 对象 | 正式 catalog schema v2 仍需独立协议升级 |
| `v2.15.10` 扩展缓存占用旧 v1 key | 识别无 contract 旧条目，按扩展规则清洗并迁移新 key | 迁移仅保留一个发布周期，后续可评估删除旧 key 兼容路径 |
| 部署覆盖远端 `.env` 后后台 500 | 构建环境剔除 secret，部署端继承远端受控赋值，拒绝空/纯空白值，并严格验证登录跳转 | 首次部署仍需显式提供认证 secret |
| RustSec `quick-xml` 两项高危公告 | 验证直接升级受 `plist ^0.39.2` 阻止；`plist 1.10.0` 又要求 Rust 1.88 | 随 Tauri 工具链与项目 MSRV 升级统一处理 |
